# ОГЭ RPG

Экшн от третьего лица для подготовки учеников 9 класса к экзамену по физике 
без физдвижка на Babylon.js + TypeScript. Реализовано «3D-сцена + управление персонажем +
пошаговый бой в виде решения задач» — дальше на этот каркас наращиваются
граф заклинаний, костры-обучение, генерация мира и т.д.

## Запуск

```bash
npm install
npm run dev
```

Откроется адрес из терминала (обычно `http://localhost:5173`). Для сборки —
`npm run build`, для предпросмотра собранной версии — `npm run preview`.

## Управление

- `WASD` / стрелки — движение (относительно текущего разворота камеры)
- Мышь (зажать и тянуть) — орбита камеры вокруг персонажа
- Колесо мыши — приблизить/отдалить камеру
- `G` — открыть/закрыть граф заклинаний
- `E` — взаимодействие с тем, что рядом: костёр / энергетический барьер /
  сундук / спарринг с уже побеждённой ("дружелюбной") ведьмой / объект для практики
- `Esc` — закрыть открытое окно

## Что уже работает

- Персонаж-болванчик в блочном стиле (roblox-эстетика), третье лицо,
  коллизии со стенами/полом без физдвижка (`checkCollisions` + `moveWithCollisions`)
- Камера-орбита вокруг игрока с мягким слежением (`ArcRotateCamera`)
- Мир генерируется процедурно при каждом запуске (5–7 секций + подход к
  башне, разная длина и число врагов) и грузится потоково — в памяти держится
  только текущая секция и её ближайшие соседи, остальное полностью
  разбирается и пересобирается заново при возвращении. Башня строится один
  раз отдельно от этой системы, поэтому видна издалека всегда
  (`src/world/WorldGenerator.ts` + `src/world/generation/`, `src/world/SectionChunk.ts`,
  `src/world/WorldStreamer.ts`, `src/world/Tower.ts`)
- Трава и кусты по границам коридора — по одному мешу-образцу на секцию,
  остальные точки — тонкие инстансы (один draw call на всю траву/кусты секции)
- Тема атаки ведьмы при генерации выбирается с уклоном в темы, которые игрок
  хуже освоил (ниже мастерство → выше шанс встретить ведьму именно на этой теме)
- Побеждённая ведьма не исчезает и не появляется враждебной заново при
  пересборке секции — она становится "дружелюбной" (снимает шляпу, светлеет,
  зелёный огонёк над головой) и с ней можно спарринговать повторно по `E`.
  Состояние учитывается в `GameState` по стабильному id, а не по ссылке на
  объект (инстансы пересоздаются при повторной загрузке секции)
- Граф заклинаний из 6 законов физики в 3 тирах с пререквизитами — открывается
  по `G`, показывает статус "изучено / доступно / заблокировано" и мастерство
  0–5 у изученных (`src/ui/SpellGraphScreen.ts`, `src/core/GameState.ts`)
- Костры (`src/entities/Bonfire.ts`, `src/learning/LearningManager.ts`):
  подошёл, нажал `E` → список тем, которые можно изучить прямо сейчас (дерево
  открыто **и** найдены книга и страница, см. ниже) → этап 1 (закон +
  формула + простой пример) → этап 2 (задача сложнее, с доп. шагом/конверсией
  единиц) → заклинание изучено. Ошибка на этапе обучения не наказывается —
  просто пробуй снова. Темы, которые уже открыты по дереву, но без материалов,
  показываются отдельным списком «Не хватает материалов» (что именно искать)
- Книги и страницы в сундуках (`src/data/books.ts`, `src/entities/Chest.ts`,
  `src/learning/chestLoot.ts`, `src/ui/ChestLootScreen.ts`): **книга = ветка
  прокачки** (одна на школу), **страница = заклинание**. Чтобы изучить
  заклинание, нужны: книга его школы (у моста — книги обеих школ), страница
  этого заклинания и изученные пререквизиты. Книги и страницы выводятся из
  данных заклинаний автоматически — добавил заклинание в JSON, и у него
  появилась страница, добавил школу — появилась книга. Сундук открывается по
  `E`, окно показывает находки и что ещё нужно, чтобы выучить найденное.
  Содержимое обычных сундуков **подбирается при открытии** под состояние игрока
  (в мир при генерации записано только число слотов): сначала самое простое,
  чередуя школы, страница никогда не выпадает раньше книги своей школы,
  дублей нет, а пропущенный сундук ничего не «сжигает». Вводные сундуки в
  первых двух секциях рукописные (книга Школы земли + две страницы в первой
  секции — без них игрок не смог бы ничего выучить до первых ворот). На
  экране графа (`G`) видно: найдена ли книга школы, сколько страниц собрано, а у
  каждой темы — чего не хватает
- Пошаговая дуэль с ведьмой (`src/combat/CombatManager.ts`): у ведьмы одна
  тема атаки — её же формулой она бьёт, и ею же вынужден защищаться игрок.
  Победить её этой темой нельзя ("она ей и так владеет") — нужно выбрать
  любое ДРУГОЕ изученное заклинание для контратаки. Раунд = защита → атака,
  побеждает тот, кто первым наберёт нужное число попаданий (3 из 3); HP у
  ведьмы нет, только счёт дуэли. Пропущенные удары ведьмы отнимают общее
  здоровье игрока (полоска в HUD). Если атаковать нечем (нет второй изученной
  темы) или дуэль проиграна — можно отступить и вернуться позже
- Ведьмы на темах, которыми игрок ещё не умеет защищаться, не пускают в бой —
  показывают подсказку найти костёр
- Энергетические барьеры между секциями (`src/entities/EnergyGate.ts`,
  `src/gates/GateManager.ts`): физически блокируют проход, требуемый тир
  растёт с прогрессом (равен тиру только что пройденной секции — то, что
  игрок к этому моменту уже должен знать). Подошёл, нажал `E` → выбрал
  заклинание нужного уровня → решил задачу → барьер разрушен навсегда
  (учитывается в `GameState` по id, переживает пересборку секции)
- Статические объекты для практики — деревца/чучела/крапива
  (`src/entities/PracticeTarget.ts`, `src/practice/PracticeManager.ts`):
  2–4 на секцию, по `E` — выбор изученного заклинания и один вопрос без
  ставок (ошибка не наказывает, верный ответ чуть поднимает мастерство)
- Три случайных стиля границ коридора вместо однообразной стены — кусты,
  металлический забор, скальная гряда (реальный коллайдер остаётся тонким и
  визуально нейтральным позади декора)
- HUD с полоской здоровья и контекстными подсказками (`src/core/Hud.ts`)
- Данные заклинаний: формула, банк боевых вопросов + отдельные обучающие
  вопросы для двух этапов костра (`src/data/spells.ts`)

## Стелс и поведение ведьм

- **Ведьмы живут.** Каждая спавнится у «дома» (первая ведьма секции — рядом со своим
  сундуком, в нише — между входом и сундуком) и вперемешку то стоит, оглядываясь,
  то медленно прогуливается недалеко от дома (`src/ai/witchBrain.ts`).
- **Зрение — конус.** Угол 70°, дальность 11 м. Обзор перекрывают стены (луч по
  `walls_*`), кусты, заросли у края коридора и деревья (круги на уровне глаз,
  `src/stealth/cover.ts`): за любым из них можно скрыться от взгляда.
- **Заметила → узнавание → погоня.** Сначала жёлтый огонёк и пауза на месте
  (0.2–0.8 с, у каждой ведьмы своя) — есть шанс успеть спрятаться; потом красный
  огонёк и медленная погоня (~2.1 м/с против 6.5 у игрока). Погони не повторяются:
  у ведьм разный характер (зоркость, скорость, реакция, терпение — `TRAIT_RANGES`),
  скорость «плавает», траектория виляет, ведьма иногда останавливается и устаёт.
- **Потеряла игрока** (куст, дерево, стена, убежал) → оранжевый огонёк: иногда сначала
  оглядывается, идёт к месту пропажи (иногда туда, куда он бежал), обходит это место
  по кругу, то и дело замирая, 2–3 с и теряет интерес. Вышел на виду — снова погоня.
- **Граница секции.** Ведьма не покидает свою секцию: игрок ушёл за границу (или
  ведьма устала/дошла до поводка) — она стоит и смотрит 3.5–8 с, пока видит игрока
  (потеряла из виду — интерес гаснет быстрее), потом возвращается. Подойдёшь близко
  (4.5 м) — снова бросится.
- **Кусты прячут.** Игрок внутри куста или зарослей у края коридора
  (`src/stealth/bushes.ts`) невидим и бой с ним не начинается. Накрывающие игрока
  кусты и сам игрок становятся полупрозрачными, в HUD — плашка «🌿 В укрытии».
- **Рощицы.** Кучки по 3–5 деревьев (`generateTreeGroves`) перекрывают обзор ведьм;
  у стволов есть коллизия; крона прозрачнеет, когда между камерой и игроком.
- **После боя** (поражение/отступление) ведьма отцепляется и 6 с не замечает игрока.
- **Кусты** редкие и небольшие: ~1 на 10 м коридора, диаметр 1.9–2.5 м, не ближе 3 м
  к сущностям и 6 м друг к другу (`BUSH_*` в `src/world/SectionContent.ts`). Кусты и
  кроны — отдельные меши (у инстансов Babylon нет своей прозрачности), у зарослей
  на время прозрачности инстанс подменяется призрачным двойником.

## Чего пока нет (следующие этапы)

- Разных типов ведьм/слабостей и комбо-боёв с мини-боссами (этап 6–7) —
  энергетические барьеры уже частично готовят почву (тир растёт по коридору),
  но настоящего комбо "несколько заклинаний подряд в одном вызове" пока нет
- Полноценной адаптивной системы под слабые темы — сейчас взвешивание при
  генерации есть, но полноценная статистика ошибок и её накопление между
  сессиями — это этап 10 (вместе с сохранением)
- Финального босса-башни как экзамена (этап 9)
- Сохранения прогресса (этап 10)
- Прочих декоративных объектов окружения (камни без функции, доп. пропсы) —
  трава/кусты/заборы/скалы и объекты практики уже есть

## Проверка генерации мира без браузера

Логика генерации/стриминга/стелса покрыта headless-тестами (не требуют браузера,
сцена — `NullEngine` из Babylon). По умолчанию тяжёлые тесты гоняют «лёгкую» выборку
сидов (хватает, чтобы ловить баги; весь `npm test` ≈ 1.5 мин и ≈ 1 ГБ памяти).
Полный прогон — по запросу:

```bash
npm test                   # всё: быстрые тесты + мировые (лёгкий режим)
npm run test:fast          # только быстрые (ИИ ведьм, стелс, контент, сундуки, лут, UI)
npm run test:world         # мировые тесты в лёгком режиме
npm run test:world:full    # те же, но на полной выборке сидов (дольше и тяжелее)
npm run test:world-gen -- --full   # любой тяжёлый тест можно запустить полным
SEEDS=200 npm run test:world-gen   # или задать число сидов (PowerShell: $env:SEEDS=200)
```

Отдельные тесты:

```bash
npm run test:world-gen        # инварианты генерации: без разрывов пола, границы
                              # секций, уникальные id, разброс ведьм друг от друга
npm run test:section-content  # «конструктор секций»: точные правила, процедура из
                              # GameState, детерминизм по seed
npm run test:world-streamer   # окно ±1 секции реально выгружает лишнее,
                              # дружелюбные ведьмы и открытые ворота переживают
                              # пересборку секции
npm run test:witch-ai         # мозг ведьмы (без Babylon): зрение, узнавание, погоня,
                              # поиск, граница секции, разнообразие поведения
npm run test:stealth          # генерация кустов/деревьев, прозрачность, укрытия от
                              # взгляда, коллизии ведьм и стволов, проксимити
npm run test:loot             # книги и страницы: правила изучения, содержимое
                              # сундуков, симуляция прохождения (у каждых ворот
                              # хватает изученных тем, без тупиков)
```

## Структура проекта

```
src/
  core/          — движковая обвязка: игрок, HUD, GameState (прогресс)
  entities/      — Witch, Bonfire, PracticeTarget, EnergyGate, Chest
  ai/            — witchBrain: состояния ведьмы (стоит/гуляет/погоня/поиск/возврат)
  stealth/       — кусты-укрытия (bushes) и StealthManager (невидимость, прозрачность, тик ведьм)
  combat/        — боевой цикл и его UI
  learning/      — обучение у костра (два этапа), содержимое сундуков (chestLoot)
  practice/      — тренировка у статических объектов (без ставок)
  gates/         — энергетические барьеры между секциями
  ui/            — экран графа заклинаний, окно находок из сундука
  world/         — генерация мира: WorldGenerator (фасад: generateWorld/extendWorld),
                   spec/ (модель данных SectionSpec/WorldSpec), geometry/ (чистая
                   геометрия дуги), math/ (детерминированный PRNG с состоянием),
                   generation/ (конфиг, фабрика секций, планировщик ворот,
                   упорядоченный конвейер расширений SectionAssembler, возобновляемый
                   TrackBuilder — основа «бесконечного» продления мира через
                   extendWorld), SectionContent (конструктор секций: точные правила
                   контента + процедура из GameState), SectionChunk (сборка/разборка
                   секции), WorldStreamer (какие секции держать в памяти),
                   Tower (башня отдельно)
  data/          — заклинания, школы и банк задач; книги и страницы (books.ts —
                   выводятся из школ и заклинаний)
  main.ts        — сборка сцены и игровой цикл
  style.css      — стили HUD, боя, графа, костра и барьеров
scripts/
  test-world-gen.ts       — инварианты процедурной генерации
  test-world-extend.ts    — продление мира секциями (extendWorld): стыки, id, детерминизм
  test-section-content.ts — конструктор секций: точные правила, процедура из состояния
  test-world-streamer.ts  — стриминг секций, дружелюбные ведьмы, ворота
```
